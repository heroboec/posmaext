# Перенесённый контекст Position Matcher

Перенос: 2026-10-30, по просьбе пользователя принять контекст Claude Code.
История разработки: 17–18 октября 2026. Код при переносе: manifest 2.8,
HEAD `d6c7652`. Исторические сведения об опубликованных релизах не проверялись
повторно в сети. Это рабочая сводка с указателями на полный оригинал, а не копия
всей переписки и сырых HTML с секретами.

## Назначение и решения пользователя

Личный инструмент для работы со списком заявок/поставок и их свойствами в админке.
Пользователь называет этот список также списком товаров. Установка на Windows без
прав администратора; дополнительные программы для обновления нежелательны.

Изначально в ZIP было большое расширение: CSV-каталог, fuzzy matching, автоматическое
сопоставление и привязка товаров, доверенные заявки, массовые статусы, сбор каталога,
снятие скрытия, очистка китайских полей и find/replace в TinyMCE. Пользователь попросил
убрать всё, кроме фильтра категорий и настроек. Позднее добавлялись только явно
заказанные функции ниже. Старые возможности не следует считать частью продукта.

Репозиторий выбран публичный: `heroboec/posmaext`. Адрес для обновлений зашит в код.
Пользователь просил убрать название реального домена из подсказки настроек, сохранив
пути: сейчас примеры `github.com/admin` и `mysite.com/bids`. Не добавлять реальный
домен в публичные примеры. Рабочие шаблоны хранятся в браузере.

Автозакрытие вкладки после сохранения обсуждалось и было явно отменено.
Thunderbird и его дополнительные окна обсуждались отдельно, реализации здесь нет.
Пользователь просил установить Superpowers; Claude сообщил, что плагин уже установлен
у него (7.0.0). Это исторический факт, не подтверждение доступности плагина в Codex.

## Текущее поведение

Версия 2.9, подготовлена к выпуску 2026-10-30: в обоих местах отклонения
доступны 12 согласованных английских шаблонов пользователя.
Выбор подставляет текст в редактируемое поле; можно написать причину вручную.
Отправляется итоговое содержимое поля, а не исходный шаблон. Выбор сам не отправляет
запрос. На списке расширение перехватывает только выбор статуса 4 в строке заявки
и открывает своё окно вместо штатного обработчика. При отмене/ошибке статус остаётся
прежним; после успеха обновляются select и отображаемая причина. Другие статусы
обрабатывает сайт. В v2.10 перехват работает на распознанных страницах /bids (включая языковой
префикс) независимо от URL-фильтра; на других путях требуется совпадение шаблона.
Штатное окно сайта (включая возможные вложения) при этом не используется.
Повторная отправка горячей клавишей во время запроса заблокирована.



С v2.13 стандартные шаблоны и их короткие названия находятся в rejection-reasons.js;
пользовательский список хранится в chrome.storage.local.declineReasons. Релиз запускается пушем тега v2.9 через существующий GitHub Actions workflow.

Исправление v2.10: окно перенесено в Shadow DOM, чтобы стили сайта не обрезали
select/textarea. В списке шаблонов короткие русские названия, в поле — полный
согласованный английский текст. Добавлены обход фокуса внутри окна и Esc с любого
контрола. `page-bridge.js` запускается в MAIN world и оборачивает
`admin_bids.change_status`: только статус 4 передаётся контент-скрипту через
отменяемое DOM-событие `pm-request-decline`. Это покрывает прямые вызовы и jQuery,
которые не создают нативный change. Если контент-скрипт не обрабатывает событие,
вызывается исходная функция сайта. Остальные статусы всегда передаются ей.
При поздней загрузке функции ожидаем её до 30 секунд. Текущая причина сбоя на живом
списке пользователя не подтверждена: исходная разметка доступна только из истории.
Проверено в локальных DOM-тестах и Chrome с конфликтующими стилями (select 44px,
textarea 150px); после обновления требуется перезагрузка открытых вкладок сайта.

Версия 2.11: массовое отклонение явно выбранных заявок. Слева в первой ячейке
каждой строки добавлен checkbox без изменения числа столбцов. Над таблицей — счётчик,
«Выбрать все видимые», «Снять выбор», «Отклонить выбранные». Панель изолирована Shadow DOM.
Пользователь явно отменил лимит 10 для этого действия; открытие вкладок и продажа
сохраняют прежний лимит. Выбор сбрасывается для скрытых фильтром, удалённых и уже
отклонённых строк; новые строки по умолчанию не отмечены. Подтверждение показывает
количество и ID выбранных заявок, предлагает общую редактируемую причину.
Отправка последовательная в порядке строк, пауза 800 мс после ответа между запросами.
Статус и наличие строки проверяются перед каждым запросом. Прогресс виден на кнопке.
Успешные строки получают статус 4 и снимаются с выбора. Ошибки перечисляются по ID,
причина остаётся в окне; «Повторить неудавшиеся» обрабатывает только оставшиеся заявки.
Во время отправки заблокированы выбор, отмена окна и остальные пакетные действия.
После завершения над таблицей остаётся итоговый счётчик и ошибки, если они были.

Версия 2.12: все операции списка распознают строки по `tr.bids-tr-table-new`,
без требования класса `tr_default`. Пользователь предоставил строку `tr_saled`
со статусом 2: именно из-за лишнего ограничения у неё не было checkbox. Исправлены
выбор, фильтрация, раскрытие деталей и наборы открытия/продажи; статус определяется
по select. Добавлена проверка смешанных классов строк, включая `tr_saled` и строку
без дополнительного класса. Персональные данные из примера в тесты не перенесены.

Версия 2.13: причины вынесены в настройки. Раздел «Причины отклонения» содержит
редактируемое поле (одна причина — одна строка), импорт .txt UTF-8, счётчик и возврат
стандартных причин. Файл заменяет черновик в поле; изменения применяются общей
кнопкой «Сохранить». Пустые строки и пробелы по краям убираются; CRLF, LF, CR и BOM
поддерживаются. Пустой сохранённый список отключает шаблоны, сохраняя ручной ввод.
Отсутствующий ключ declineReasons использует прежние 12 причин по умолчанию.
Общий файл rejection-reasons.js подключается перед options.js и content.js.
Стандартным текстам соответствуют прежние короткие русские названия; для новых
название берётся из текста (до 80 символов), полный текст сохраняется и отправляется.
Список действует в обоих одиночных окнах и при массовом отклонении. Открытые вкладки
получают изменения через storage.onChanged; уже открытое окно сохраняет собственный
снимок шаблонов и введённую причину, новый список виден при следующем открытии окна.
Импорт и ошибки чтения/сохранения проверены в tests/options.cjs, отправка и обновление
списка — в tests/decline.cjs. Настройки визуально проверены в Chrome.

Версия 2.14: пользователь отменил встроенные причины по умолчанию. В runtime нет
ни стандартного списка, ни его коротких названий; отсутствующий/некорректный ключ
хранилища означает пустой список. Кнопка восстановления стандартных причин удалена.
Уже явно сохранённые пользователем списки не удаляются. Пользователь сам загружает
нужные строки в настройках. Ручной ввод причины доступен и без шаблонов.
Пользовательские тексты хранятся только вне репозитория и в настройках браузера.
Тесты используют синтетические сообщения.

- Фильтр категорий и раскрытие/сворачивание деталей на списке заявок. Несколько категорий
  можно выбирать одновременно. Категории извлекаются из DOM; новые строки учитывает
  MutationObserver с задержкой 150 мс.
- Фильтр запускается, если URL содержит хотя бы один сохранённый шаблон (`includes`,
  не регулярное выражение). На странице macro-values панель не показывается.
- «Править значения»: фоновые вкладки для первых 10 видимых заявок сверху вниз,
  задержка между действиями 800 мс (исходные 700 мс заменены по просьбе пользователя).
  Порядок относится к обработке DOM; service worker вставляет вкладку рядом с исходной.
- «В продаже»: тот же набор первых 10 видимых заявок; внутри него выбираются статусы
  2, 6, 7. Неподходящие заявки не заменяются следующими за десятой. Подтверждение
  содержит ID; select получает 3 и событие change с bubbles. Задержка 800 мс.
  Обе пакетные кнопки блокируются на время операции, отображается прогресс.
- На странице свойств целые блоки полей переставляются: обязательные текстовые,
  необязательные текстовые, затем остальные (включая select). Внутри групп порядок
  стабильный, значения сохраняются. Определение обязательности: required или .red.
- Плавающая кнопка сохранения вызывает `form.requestSubmit(realBtn)` с нативной
  валидацией. Эта страница обрабатывается по наличию формы независимо от URL-шаблонов.
- Плавающая кнопка отклонения открывает окно с обязательной причиной. Esc/клик снаружи
  закрывает; Ctrl+Enter/Meta+Enter отправляет. Во время запроса поля блокируются.
  При ошибке причина остаётся; при успехе кнопка отключается и показывает ID заявки.

## Файлы и технические детали

Простой JavaScript без сборки. `extension/manifest.json`: Chrome MV3, storage,
content scripts на `<all_urls>` при document_idle, options.html, background.js.

- `content.js`: фильтр, пакетные действия, сортировка формы, сохранение, отклонение.
- `content.css`: фиксированная панель слева (top 60px), кнопки сохранения/отклонения
  справа снизу (24/76px), окно причины и скрытие отфильтрованных строк.
- `background.js`: открывает настройки по значку, фоновые вкладки через tabs.create,
  удаляет старые ключи хранилища при установке/обновлении.
- `options.html`, `options.js`: шаблоны адресов, текущая версия, проверка релиза,
  ссылка на ZIP, перезагрузка расширения.
- `.github/workflows/release.yml`: по тегу v* проверяет совпадение тега с manifest,
  собирает содержимое extension в `position-matcher-vVERSION.zip`, публикует релиз.
- `.gitignore`: ZIP, CSV, PDF и .idea.

Контент-скрипт изолирован от JavaScript страницы: прямой доступ к window.bids обычно
отсутствует. Для раскрытия есть fallback через display у строки деталей. Если сайт
загружает детали только при клике, это требует отдельной проверки. Для статуса
используется DOM change, вызывающий обработчик страницы. Открытие вкладок вынесено
в background, чтобы не зависеть от блокировщика всплывающих окон.

Отклонение: POST на `${location.origin}/req/bids.php`, credentials include.
Content-Type: application/x-www-form-urlencoded; charset=UTF-8;
x-requested-with: XMLHttpRequest; x-csrf-token берётся из meta страницы.
Поля: `act=bids`, `do=change_status`, `bid_id`, `status=4`, `message` (причина).
ID извлекается из окончания action формы, fallback — pathname.
Статусы: 1 ожидает загрузки, 8 в обработке, 2 на проверке, 6/7 на проверке 48/72ч,
3 аккаунты в продаже, 4 отклонено, 5 аккаунты проданы.

## Проверки и незакрытые вопросы

По истории Claude проверял синтаксис и использовал jsdom 24.1.3: сортировку,
requestSubmit, лимит и интервалы открытия, перевод review-статусов через onchange,
формат запроса отклонения и сохранение окна при ошибке. Живую админку не тестировал.
При переносе эти проверки заново не запускались: меняется только документация.

Скрипты тестов на момент переноса существуют в scratchpad (путь ниже): test_macro.js,
test_batch.js, test_decline.js, рядом node_modules. Это временные локальные материалы,
не установленная тестовая инфраструктура репозитория.

Для доработки шаблонов добавлен `tests/decline.cjs` (node:test + jsdom 24.1.3).
Запуск: `NODE_PATH=<scratchpad>/node_modules node --test tests/*.cjs`,
либо `node --test tests/*.cjs` при установленном jsdom. Двадцать два теста проверяют
оба места, редактирование и ручной ввод, payload, отмену, повторную попытку,
защиту от двойной отправки, новые строки и сохранение штатных обработчиков,
а также пакет из 12 заявок, общую причину, порядок и интервалы, частичный отказ и
повторную попытку без повторной отправки успешных заявок, отмену и снятие скрытых строк.

Неизвестен точный успешный ответ сервера на смену статуса: текущий код отклонения
считает успехом HTTP ok без json.status === 'error' и без json.error. В том числе
ответ не в JSON может считаться успехом. Реальные модальные окна сайта при массовой
смене статуса тоже не проверены. Вложения к отклонению не реализованы; Claude спросил
о необходимости, ответа в истории нет. Это не согласованная новая задача.

Последний вопрос пользователя в старом диалоге: были ли свойства поставщика в HTML
списка? Да: в скрытых строках деталей есть macro display rows, страна, формат,
прокси и другие данные; связанный товар каталога находится в основной строке.
Следующее действие над этими данными пользователь тогда не определил.
